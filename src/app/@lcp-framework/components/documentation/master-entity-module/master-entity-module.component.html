Master Entity

Introduction

The Master Entity page is a powerful tool that allows users to manage and interact with a list of entities stored in the backend database. This page presents the data in a common datatable format, making it easy to view, filter, and manipulate the information. The Master Entity is designed to be highly flexible, accommodating various use cases by allowing customization of the data presentation, filtering options, and export capabilities. It serves as a central point for managing different entities across the application, streamlining workflows and enhancing productivity.

Master Entity Add/Edit Screen:

The Master Entity Add/Edit screen is designed to provide a seamless experience for creating and managing entities within the system. This screen allows users to define the parameters of a new entity or modify an existing one. Below are the key fields and functionalities available on this screen:

  • Entity Name:This is the name of the entity being created or edited. For example, the entity name could be "User Grid."
  • Entity Type: Defines the type of entity being managed. In this case, it could be a "Grid Builder Module," which specifies that the entity is a part of the grid-building framework within the application.
  • Choose Entity Permission: This section allows you to assign permissions to the entity, including options like view, add, edit, delete, view details, and export. These permissions control what actions users can perform on this entity.
  • Primary Table: This is the main database table associated with the entity. For example, the primary table could be 'users,' indicating that the data for this entity will be fetched from the users' table.
  • Query Information: This section is crucial for defining how data is fetched and displayed for the entity. It includes:
    • Includes:Specifies the tables to be joined with the primary table and the join conditions. For example, in a query, you might join the 'users' table with another table to retrieve additional related information.
    • Group By:Defines the fields by which the data should be grouped. Grouping helps in aggregating data and displaying it in a meaningful way.
    • Order By:Specifies the order in which the data should be sorted. This ensures that the data is displayed in a logical and user-friendly manner.
